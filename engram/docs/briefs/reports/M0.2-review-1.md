## Exit criterion check (PLAN.md §10.2 M0.2)

- **`make test-integration` green**: met. 70 s wall with `ENGRAM_TEST_DOCKER_HOST_NETWORK=1`, 59 s with
  `ENGRAM_TEST_PG_DSN`; within the 6 min T3 budget. The latency gates did not run as gates (F7).
- **`--check-rls` returns zero rows**: met. `engramctl migrate --check-rls` on a fresh migrated database: no output,
  exit 0; 180 namespace-scoped relations (52 tables, 128 partitions) all ENABLE + FORCE. It reports a dropped
  partition policy, an altered qualifier and a permissive `move_target_*` policy; it misses transitive `BYPASSRLS`
  membership and definer views (F3).
- **BM25 arm keeps Top-K pushdown under RLS on the real image**: met for the RLS-shaped predicate only. As
  `engram_app`: `Merge Append` → `Subplans Removed: 15` → `Custom Scan (ParadeDB Base Scan) on facts_p10`, `Exec
  Method: TopKScanExecState`, `Scores: true`, `TopK Order By: pdb.score() desc, memory_id asc`, the namespace as a
  Tantivy `term`, 28.6 ms. The §3.8 text (`namespace_id = $1`) fails as a literal, as a `PREPARE` custom plan and as a
  generic plan (`Result` / `One-Time Filter` above the scan, `Scores: false`, `ERROR: Unsupported query shape`);
  `mentioned_at <= 'infinity'` fails with `json cannot be converted to term`. The §8.4.4 p95 clause is not verified
  (F2).
- **Trigram lookup via the `SECURITY DEFINER` wrapper is an index scan ≤ 10 ms as `engram_app` (308 ms unwrapped)**:
  met for the plan's own case. Wrapped `'kestrel corp'` 2.4 ms, `entities_trgm_idx` `idx_scan` 0 → 4 after four calls;
  the wrapper refuses another namespace (42501); unwrapped as `engram_app`: `Result` (`One-Time Filter`) → `Seq Scan
  on entities`, 2,951 buffers, 284 ms over 100,001 rows. Not met for a non-selective query (F9).
- **Tags resolve outside RLS**: met in the arm sense (no arm table carries document tags); the resolution statement
  runs a non-leakproof operator under RLS and the GIN index is unusable for `engram_app` (F8, CONFLICTS #14.6).
- **No generated column exists**: met. `attgenerated <> ''` count 0 on the migrated database; `pg_dump` shows none;
  self-check 12 present.
