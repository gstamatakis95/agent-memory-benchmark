## Findings, conflicts, deviations (numbered; the orchestrator may fold them into CONFLICTS.md)

1. REAL DEFECT FIXED (errs): `ErrorInfo.metadata` is a protobuf map and the default encoding orders map entries
   differently per call, so `ToStatus` and `ToConnect` could emit different bytes for one error and a golden flaked.
   Details are now packed with `proto.MarshalOptions{Deterministic: true}` (`packDetail`);
   `TestDetailBytesAreDeterministic` pins it. This is exactly what the byte-identity clause is about.
2. CONFLICT (DeadlineGuard): the brief and section 1.3 step 1 say "clamped to the class caps"; N11, section 4.1.2
   ("Exceeding the cap is INVALID_ARGUMENT, not a silent clamp"), `api.Options.MaxDeadline` and the M0.1 stub's own doc
   say enforced, never clamped. Implemented per the register (higher precedence): over the cap is INVALID_ARGUMENT
   `DEADLINE_TOO_LONG`. Section 1.3's wording should read "validates" (needs a text fix in the plan). The minimum of
   section 4.1.2 is enforced as `OUT_OF_RANGE` with a fixed 20 ms transit allowance (fix round F11; it was 50 %: the
   server sees the client's deadline minus the transit time, and refusing a client that asked for exactly the minimum
   would be a bug). The 20 ms is mine (CONFLICTS.md #21); the plan
   gives none.
3. GAP (N65): "`entry.group` in `claims.ns_group`" has no column. Neither the catalog DDL nor `Namespace` in
   `namespace.proto` stores a group. Reading implemented: `catalog.Entry.Group`, read from `namespaces.profile ->>
   'group'` (`profile` is "identity, never inherited", a trigger already logs its changes), written by
   `CreateParams.Group`. Needs a ruling: a `group` column (expand-only migration) or this reading, and the
   `Namespace.group` proto field `CreateNamespace` would set.
4. DEVIATION (migration): the reference grants `ON ALL TABLES` / `ON ALL FUNCTIONS IN SCHEMA public`. Applied as
   `catalog_migrate` that fails (goose's version table belongs to the bootstrap superuser; the ParadeDB template
   preinstalls `pg_stat_statements_reset` etc. in `public`). The migration names the catalog's own relations and
   functions; a later migration that adds one grants it. Same family as CONFLICTS.md #14. Migration 0001, like the
   shard's, does NOT need a superuser: a LOGIN CREATEROLE bootstrap role with ADMIN OPTION on pg_read_all_stats,
   database
   ownership and createrole_self_grant = 'set, inherit' suffices (fix round F15, T3-tested; the earlier claim here was
   wrong). Down drops the catalog's
   objects and leaves extension-owned relations alone.
5. DEVIATION (inputs): `catalog.CreateParams` gains `Namespace id.NamespaceID` (zero mints a UUIDv7; a retry after a
   lost ack reuses the id) and `Group string`; `catalog.AutoShard` (`-1`) asks for `pick_shard`; `ResolverOptions` gains
   `NegativeStaleTTL`, `LoadTimeout`, `ProbeInterval`, `ReconnectMin`, `ReconnectMax`, `Clock` (all optional,
   documented defaults); `authz.InterceptorOptions` (an options struct, not option funcs) carries `Public`, `Cells`,
   `Config`. No existing signature changed.
6. SCOPE (what `catalog.Postgres` implements): `Namespaces` (Resolve, ResolveByName, Create, SetState, BumpEpoch) and
   `Listener`. NOT implemented, in this branch: `NamespaceAdmin`, `Tenants`, `TenantOps`, `Registry`, `Moves`,
   `MoveStamps`, `MoveReader`, `ReplayFloor` (the brief names the Resolver, the Postgres-backed catalog and the
   doubles; the move ledger CAS and the `Plan/Advance/Commit/Cutover/Rollback` state-machine test of section 2.2.3 are
   M1.5's), `Reconciler`, `Replication`, `AckAfterReplay` (E1). `request_id` idempotency of `Create` (N184,
   `idempotency_keys`) is also E1's. If "the Postgres-backed catalog" means all of section 2.2.3, say so.
7. DECISION (tenant-level cross-tenant answer): section 4.1.1 specifies NOT_FOUND for another tenant's namespace; for
   a tenant-level method (CreateNamespace, GetTenant, ...) with `tenant_id` of another tenant the plan says only "the
   tenant-bound check is enforced". Implemented NOT_FOUND `NotFound{TENANT}` (no existence oracle for tenants either);
   the alternative is PERMISSION_DENIED. Open question.
8. DECISION (rate buckets): only Recall (`recalls_per_min`) and Retain (`retains_per_min`) are metered (D13 names no
   other bucket); Reflect is unmetered by the interceptor (it is bounded by its deadline and `quota.Reserve`, N130).
   `quota.Decision` carries no limit or current value, so the `QuotaExceeded` detail has `limit`/`current` 0 and scope
   NAMESPACE. Open question for M1.x if clients need the numbers.
9. DECISION (closed table): a method that is not in the `Policy` and not in `InterceptorOptions.Public` is
   PERMISSION_DENIED; wiring must list gRPC health and reflection as public. `DeadlineGuard` skips everything outside
   `memory.v1` and `memory.admin.v1`.
10. DECISION (token shape): a token with `tenant_id` must not carry `engram.operator` or `engram.worker`, and the
    verifier's audience list is what keeps an operator token off the tenant route (one verifier per listener).
11. DECISION (JWKS): the key set is served from cache through an issuer outage; with no key set at all the answer is
    UNAVAILABLE, not UNAUTHENTICATED (the verifier cannot tell whether the token is good). Plan: "Failure ->
    UNAUTHENTICATED" for an invalid token; an unreachable issuer is not an invalid token.
12. DECISION (Resolver): `Flush` (every LISTEN (re)subscription and every unreadable payload) also clears the
    catalog-down state, because it proves the catalog reachable; without that, the first resolve after a reconnect
    failed fast for one probe interval (found by the rapid model). A `tenant` notification drops every cached
    namespace of the tenant (the trigger emits no namespace id for it); a `shard` event drops that shard's entries
    (no trigger emits one today). The age gauge is `StaleAge()`/`Stats()`; registering it with `internal/telemetry` is
    the composition root's job (`catalog` may not import `telemetry`).
13. MERGE NOTES: M0.2's `migrations/embed.go` declares package `migrations` with `Shard`; mine is
    `migrations/catalog.go` with `Catalog`, so the two merge without a conflict (two package doc comments concatenate).
    `go.mod` adds pgx v5.7.6 and goose v3.26.0 (the same versions M0.2 uses), golang-jwt v5.3.0 and
    pgregory.net/rapid v1.2.0 (promoted from indirect). The private harness is gone (fix round F4): the catalog tests
    use the shared testcontainers-go harness `internal/store/pgtest`; the earlier text here described the private
    one, which honoured
    `ENGRAM_TEST_PG_DSN` and `ENGRAM_TEST_DOCKER_HOST_NETWORK=1` and starts the pinned digest.
14. PRE-EXISTING, NOT MINE: `make test-prop` fails on this base. The recipe passes `-rapid.checks=200` to every
    package under `./internal/...`, and a package that does not import `pgregory.net/rapid` rejects the unknown flag
    ("flag provided but not defined", then `go test` prints its usage and exits 1; for the first package listed it
    reports "no Go files in ."). The Makefile is M0.1's file; the fix is to pass the flag only to packages that import
    rapid (or `-args`-less env var). I ran the property tests directly:
    `go test -run 'Prop|Property|^Test[A-Za-z]+_[A-Za-z]+$' ./internal/catalog/ ./internal/authz/ -rapid.checks=200`.
15. NOTE: the `catalog_events` trigger for `shard` rows does not exist in the reference DDL although
    `catalog_events.kind` allows `'shard'`; shard state changes therefore never invalidate cached entries (they do not
    change `shard_id`/`epoch`/`state` of a namespace, so nothing is stale; recorded for the move/registry author).
