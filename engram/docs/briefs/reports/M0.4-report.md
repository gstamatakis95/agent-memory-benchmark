## Compose in this environment (CONFLICTS.md #3)

`docker compose` DOES run here with `network_mode: host` and distinct ports: the whole stack (shard, catalog pair,
agent, Temporal x4, MinIO, Envoy) started and passed `make e2e`, so the fallback of the brief (hand-started
containers) was not needed. What made the sandbox hard was not networking but the Docker storage driver: until the
orchestrator switched the daemon from vfs to overlay2, every container and every layer was a full copy and the disk
filled several times (other workers shared it); I worked around it (one-layer Dockerfile, `--rm` one-shot jobs, `--no-
deps`, a posix pgBackRest repository option) and those measures are harmless to keep. Proposed CONFLICTS.md entry: #3
can be narrowed to "no bridge network; compose with host networking works; vfs storage driver is unusable for multi-
container stacks".
