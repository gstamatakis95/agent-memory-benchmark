## On the questions the coordinator asked

- `Options.Worker`: sound for workflow tasks under the default panic policy (the panic becomes a failed workflow task
  that the server retries with backoff; the worker process survives; the e2e legs prove the task fails and no activity
  runs). Not sound on the activity path because of M3, and conditional as m17 says. A poisoned task cannot hot-loop a
  worker, but a payload no worker can ever decode keeps its workflow RUNNING until the run timeout, so it needs the
  workflow-task-failure alert.
- Per-kind `gucs.yaml`: the dev values and the kind overrides are consistent with N163 (asynchronous standby, empty
  `synchronous_standby_names` on the catalog only, standby ≥ primary for senders, slots and connections); the prod
  column for non-shard kinds is m18.
- `max_slot_wal_keep_size` (64 GB prod, 2 GB dev): a worker choice; the plan gives no value; labelled in the table.
- m14: the note now scopes its number honestly (rig-bound, archiving status stated, write-path reading withdrawn);
  n8 is cosmetic.
