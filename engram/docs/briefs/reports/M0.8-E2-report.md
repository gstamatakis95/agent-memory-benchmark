## `make gen-docs` (cmd/gendocs, scripts/gen-docs.sh)

Design decision (the recommended choice of the brief, taken): generate into `docs/generated/` and read
`docs/plan/PLAN.md` read-only. The generator is a Go program, `cmd/gendocs`, because it must parse four formats (SQL,
proto with comments, YAML, Markdown) and the Go sources, and a script would not give the Go type information
`internal/errs` and `internal/prompts` provide. Protos are compiled with `protocompile` (the compiler `buf` uses), so
the comments the documents quote are the ones `buf lint` saw. `scripts/gen-docs.sh` is a thin wrapper (`--check`
writes nothing and fails when a generated file differs); the Makefile recipe was already `scripts/gen-docs.sh` and is
unchanged.

Outputs, their sources and the checks that can fail the run:

- `ownership-transitions.md`: the rows of `ownership_transitions` in `migrations/shard`, with the statement of every
  edge and role. No check beyond parsing.
- `events.md`: `events.proto` (envelope, payload variants, messages). No check.
- `enum-checks.md`: the enum types and `CHECK (col IN (...))` lists of both DDLs. No check.
- `errors.md`: the comments of `memory/v1/errors.proto`, `internal/errs` and PLAN.md 4.1.6. Fails when the gRPC code of
  a detail differs in two of the three.
- `gucs.md`: `deploy/postgres/gucs.yaml` (the path is a flag, `GUCS_YAML` in the script). Fails on a malformed table.
- `constants.md` and `internal/gen/constants/constants_gen.go`: `cmd/gendocs/constants.yaml`. Fails on a row or section
  the plan lacks, a witness text the cited rows do not contain, or a connection budget that does not add up.
- `enum-lint.md`: `cmd/gendocs/enums.yaml` (13 concepts). Fails when two sources of one concept differ.
- `prompts.md`: `prompts/*/v*/`. Fails on a file edited under its HASH pin and on a missing pin.
- `test-index.md`: PLAN.md 8 and 10.2, the Go test files and `cmd/gendocs/local-tests.txt`. Fails on the Test-name
  rules.

Choices to confirm:

- The GUC table is generated from `/home/user/engram-wt/m0.4-compose/deploy/postgres/gucs.yaml` (M0.4 is unmerged). On
  `main` the default path `deploy/postgres/gucs.yaml` does not exist yet: gendocs then prints a notice and leaves the
  committed `gucs.md` as it is; once M0.4 merges the file is read and CI covers it. The file is moving (it grew an
  `unsized:` block while I worked), so the YAML decode is not strict.
- The generated Go table lives in `internal/gen/constants` (a sibling of `internal/prompts`), not in `internal/config`,
  because `internal/config` is E3's. The package imports only `time`; no depguard rule is needed (the catch-all
  `default_internal` already allows the standard library).
- The register constants are an input table (`constants.yaml`) that is checked against the plan, not scraped from it:
  the plan states them in prose and tables of no fixed shape. Every entry cites register rows or a section and a
  witness text; whitespace-insensitive containment in the union of the cited texts is required.
- A run that finds problems writes nothing and prints every problem.
- `table-classes.md` (added late): the class tag of each of the 56 shard tables, read from the `FOREACH ... COMMENT ON
  TABLE 'class: <tag>'` lists of `migrations/shard/0002` (N113, N137 say the sections "render from" that one list).
  Fails on a table without a class, a table in two classes, or a listed table no migration creates.
- `constants.yaml` holds about 100 constants and the 10 retry policies of 5.0; the connection budget is verified to add
  up (components + 2 x P = 63, under `max_connections` 100).
