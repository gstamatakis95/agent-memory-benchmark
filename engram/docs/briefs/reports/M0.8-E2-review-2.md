### R2 (Minor): the rendered heading path and the hashed one are separate fields

- Finding: `ExtractInput` carries `Header` (rendered, "summary > heading path") and `HeadingPath` (hashed) side by
  side, so a caller can render one heading path and hash another; the struct no longer lets the summary into the key,
  but it does not bind the key to what the prompt shows.
- Evidence: `ExtractInputs` renders `in.Header`; `RenderHash` hashes `in.HeadingPath`; nothing checks that `Header`
  ends with `HeadingPath`.
- Fix: replace `Header` by `Summary` and let `ExtractInputs` build the header as `Summary + " > " + HeadingPath`, or
  have `ExtractInputs` reject a header that does not end with the heading path.

### R3 (Minor): the merge-base checks see no base in GitHub CI

- Finding: the N177 ratchet (`baseLocalTests`) and the released-golden guard (`releasedAt`) read `origin/main` or
  `main`; `ci.yml` checks out with the default depth 1, so a pull-request build has neither ref and both checks are
  skipped there for good, not only until the list reaches `main`.
- Evidence: `actions/checkout` step without `fetch-depth`; `baseLocalTests` returns nil when `git show` fails, which
  skips the growth check. On this machine (no remote, CONFLICTS.md #2) the local `main` exists, so the ratchet bites
  in the worktrees once the list is on `main`.
- Fix: fetch the base in the gen-docs job (`git fetch --depth=1 origin main` before `make gen-docs`) and make a
  missing base an error in CI (an environment switch), so the check cannot silently turn off.
